Getting Started

What is OpPay?

OpPay is a drop-in Bitcoin payment widget that any website can embed with a single script tag. It runs on the OPNet Bitcoin Layer 1 smart contract platform — no banks, no intermediaries, no KYC.

🔌
One script tag
Add one line to your HTML and you have a fully functional Bitcoin payment modal.
₿
Real Bitcoin L1
Payments settle on Bitcoin Layer 1 via OPNet. No wrapped tokens, no bridges.
🌍
Borderless
Anyone in the world can pay — no bank account, no card, no geographic limits.
ℹ️
OPNet Testnet
OpPay currently runs on OPNet Testnet (Signet fork). Use networks.opnetTestnet from @btc-vision/bitcoin. Mainnet launch is planned after audits.
Payment Methods

Three ways to pay

OpPay gives customers three payment options in the same modal. You don't need to configure anything — all three are available by default.

📱
OPNet Wallet App SAFEST
Works like iDEAL — a QR code appears in the payment modal. The customer opens the OPNet mobile wallet app, taps the scan button, and points their camera at the code. The app broadcasts the transaction directly from the phone. No browser wallet connection needed — private keys never leave the device.
No connection required Auto-detected on-chain
₿
Bitcoin Address (QR)
A unique Bitcoin address and QR code is shown for the session. The customer scans it with any Bitcoin wallet (BlueWallet, Exodus, Muun, etc.) or copies the address and sends from an exchange. The backend monitors the address and confirms when funds arrive — no wallet extension required.
Any Bitcoin wallet 1 block confirmation
🔒
OpCredit — Pay Later BUYER PROTECTED
Inspired by Klarna. The customer locks BTC in an OPNet smart contract escrow. The merchant sees the locked funds and ships the order. After delivery the customer clicks "Confirm Received" and BTC goes to the merchant. If the order is returned, the customer disputes and BTC is refunded. Auto-releases after 14 days if no action. Fully anonymous — no name, email or address required.
Anonymous Escrow protected 14-day auto-release
Payment Flow

Step by step

Here's exactly what happens from the moment a customer clicks Pay to when funds hit your wallet.

1
Customer clicks Pay
Your website calls OpPay.open() with the amount and description. The modal opens with a smooth animation. The customer sees the EUR amount and BTC equivalent.
2
Your server creates a session
Before or when the modal opens, your backend calls POST /api/sessions with your API key. The server derives a unique Bitcoin address for this payment (using your xpub HD wallet) and returns a session_id.
Server-side only
3
Customer chooses method and pays
The customer selects a payment method: OPNet Wallet App (scan QR with phone app — like iDEAL), Bitcoin Address (scan QR with any Bitcoin wallet), or OpCredit (lock BTC in escrow, pay after delivery). No browser wallet connection needed for the QR methods — the private key never leaves the customer's device.
4
OpPay monitors the address
The OpPay backend polls the OPNet RPC every 15 seconds for a balance on the payment address. When BTC is detected (within 0.5% tolerance), the session status updates to detected then confirmed.
Polling every 15s
5
Webhook fires + dashboard updates
Your registered webhook URL receives a signed POST request with the payment details. At the same time, your merchant dashboard updates in real time via WebSocket. The customer sees a confirmation screen.
Real-time via WebSocket
6
Funds available for withdrawal
Confirmed payments appear in your dashboard balance. You can withdraw to any Bitcoin address at any time from the Withdraw page. OpCredit escrow funds are released after 14 days or when the customer confirms receipt.
For Merchants

Integration guide

Adding OpPay to any website takes about 5 minutes. Here's the complete guide.

Step 1 — Include the script

Add one line inside your <head> tag:

HTML
<script src="https://cdn.oppay.io/v1/pay.js"></script>

Step 2 — Create a session on your server

When a customer is ready to checkout, your server creates a payment session. Never do this on the frontend — it exposes your API key.

Node.js (your backend)
const res = await fetch('http://your-oppay-server/api/sessions', { method: 'POST', headers: { 'Authorization': 'Bearer op_live_your_api_key', 'Content-Type': 'application/json', }, body: JSON.stringify({ amount: 49.99, currency: 'USD', // EUR | USD | GBP | JPY | CHF | AUD | CAD description: 'Order #1234 — Running Shoes', method: 'bitcoin', // 'bitcoin' | 'opcredit' metadata: { order_id: '1234', user_id: 'u_abc' }, }), }); const { session_id, btc_address, amount_btc, amount, currency, qr_uri } = await res.json();

Step 3 — Open the payment modal

Pass the session_id back to the frontend and open the modal:

JavaScript (frontend)
async function checkout() { // 1. Get session from YOUR backend const { session_id, amount_btc } = await fetch('/api/create-payment', { method: 'POST', body: JSON.stringify({ product_id: 'shoes-42' }), }).then(r => r.json()); // 2. Open the OpPay modal OpPay.open({ session_id, amount: 49.99, // for display only btc: amount_btc, merchant: 'My Shop', description: 'Running Shoes #42', onSuccess: (d) => { // d.txId, d.method, d.amount, d.escrowId (if opcredit) window.location.href = '/order/success?tx=' + d.txId; }, onCancel: () => console.log('user cancelled'), }); }
⚠️
Never expose your API key on the frontend
Your op_live_... key must only be used server-side. It gives full access to create sessions and manage your merchant account. Use environment variables and never commit it to git.

Option B — Hosted Checkout (redirect flow)

Instead of embedding a modal, redirect the customer to OpPay's hosted checkout page — similar to iDEAL or Stripe Checkout. After payment they are sent back to your site automatically.

URL
checkout.html?session=SESSION_ID&amount=49.99&currency=USD&btc=0.000473 &merchant=MyShop&desc=Order+1234&return_url=https://myshop.com/confirm&order_id=12345

After the customer pays, they are redirected to your return_url with the following query parameters:

Redirect
https://myshop.com/confirm?session_id=X&status=confirmed&tx=X&order_id=X
💡
Good for: redirect-style shops
Use the hosted checkout page if you want an iDEAL-style redirect flow instead of an embedded modal — no JavaScript SDK required on your page.

Optional — Data attributes (no-JS mode)

For simple static sites you can use data attributes — no JavaScript needed:

HTML
<button class="oppay-btn" data-oppay-amount="29.99" data-oppay-btc="0.000299" data-oppay-merchant="My Shop" data-oppay-description="Order #5678" onclick="OpPay.open(this)"> ₿ Pay with Bitcoin </button>
Server

Backend setup

OpPay includes a ready-to-run Node.js backend. Run it on your server or locally for development.

Requirements

🟢
Node.js v24+
Uses the built-in node:sqlite module — no native compilation needed on Windows, Mac, or Linux.
₿
Bitcoin xpub key
An HD wallet extended public key so OpPay can derive unique addresses per payment. Or a single static payout address.

Install & start

Terminal
# Install dependencies cd pay/backend npm install # Configure environment cp .env.example .env # Edit .env — add your WEBHOOK_SECRET, etc. # Start the server npm start # → http://localhost:3001 # → ws://localhost:3001

Register your merchant account

Once the server is running, register from the dashboard or via the API:

curl
curl -X POST http://localhost:3001/api/auth/register \ -H "Content-Type: application/json" \ -d '{"name":"My Shop","email":"me@shop.com","password":"secret123","payout_address":"bc1q..."}' # Response: { "id": "uuid-...", "api_key": "op_live_xxxxxxxxxxxx", ← save this! "pub_key": "op_pub_xxxxxxxxxxxx", "name": "My Shop" }
💡
Use an xpub for unique addresses
Set your xpub in account settings. OpPay will derive a fresh child address for every payment using path m/0/{index}, preventing address reuse and making it easy to track which payment is which.
Notifications

Webhooks

OpPay sends a signed POST request to your webhook URL whenever a payment is confirmed or an escrow is released.

Configure your webhook URL

Set your URL in the merchant dashboard under API & Embed → Webhook URL, or via the API:

curl
curl -X PUT http://localhost:3001/api/settings \ -H "Authorization: Bearer op_live_your_key" \ -H "Content-Type: application/json" \ -d '{"webhook_url":"https://yourshop.com/api/oppay-webhook"}'

Webhook payload

JSON payload
{ "event": "payment.confirmed", // or "escrow.released" "session_id": "uuid-...", "tx_id": "uuid-...", "tx_hash": "0xabc123...", "amount": 49.99, "currency": "USD", // the currency you specified "amount_eur": 46.29, // always included for your records "amount_btc": 0.000495, "method": "bitcoin", // 'opnet' | 'bitcoin' | 'opcredit' "description": "Order #1234", "metadata": { "order_id": "1234" }, "timestamp": 1712345678901 }

Return & dispute events

In addition to payment events, OpPay fires the following events for the return flow:

EventFired when
return.requestedCustomer calls POST /api/sessions/:id/refund — BTC stays locked, merchant is notified.
return.confirmedMerchant confirms receipt via POST /api/sessions/:id/confirm-return — BTC is returned to the customer.
return.auto_approvedFired after 7 days if the merchant has not responded to a return request — refund is auto-approved.

Verify the signature

Every webhook includes an X-OpPay-Signature header. Always verify it to prevent spoofing:

Node.js — verify webhook
import { createHmac } from 'crypto'; function verifyOpPay(body, signature, secret) { const expected = 'sha256=' + createHmac('sha256', secret) .update(JSON.stringify(body)).digest('hex'); return expected === signature; } // In your Express handler: app.post('/api/oppay-webhook', (req, res) => { const sig = req.headers['x-oppay-signature']; if (!verifyOpPay(req.body, sig, process.env.OPPAY_SECRET)) { return res.status(401).json({ error: 'Invalid signature' }); } const { event, session_id, amount_eur, metadata } = req.body; if (event === 'payment.confirmed') { // Mark order as paid in your database await markOrderPaid(metadata.order_id, amount_eur); } res.json({ ok: true }); });
🔁
Automatic retries
If your endpoint returns a non-2xx response, OpPay will retry the webhook up to 3 times — after 30 seconds, then 60 seconds. Make your handler idempotent using session_id or tx_id as a deduplication key.

OpCredit escrow withdrawals

🔒
Escrow funds are separate
OpCredit payments show as Escrowed in your dashboard, not Confirmed. They are locked in an OPNet smart contract. They become available for withdrawal when:

• Customer confirms receipt — instant release, status → Confirmed
• 14 days pass — auto-release by the backend hourly cron job

FAQ

Frequently asked questions

Do I need to run the backend myself? +

Yes, for production you need to run the OpPay backend on your own server. This gives you full control over your funds. There is no hosted version — your API keys and BTC addresses are yours alone.

What is the fee for using OpPay? +

OpPay itself charges no fees. You only pay the Bitcoin network fee (~0.000003 BTC per transaction) which goes to Bitcoin miners — not to OpPay. This makes it far cheaper than card processing fees (which are typically 1.5–3.5%).

What happens if the customer underpays? +

OpPay has a 0.5% tolerance for underpayments to account for rounding and minor BTC price fluctuations. If a payment is more than 0.5% below the expected amount, the session will not confirm automatically.

How does OpCredit work for merchants? +

When a customer uses OpCredit, you can see their BTC is locked in the OPNet smart contract from your dashboard (status: Escrowed). Ship the order normally. Once the customer confirms receipt, the BTC is released to your account. If they don't respond, it auto-releases after 14 days.

Can I use OpPay with React, Vue, or Next.js? +

Yes. The SDK is a plain JavaScript library — include it via a <script> tag and call OpPay.open() from any framework. For Next.js, load it with next/script and call from a click handler. A React npm package is planned.
